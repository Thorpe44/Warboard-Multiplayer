# WARBOARD v47 — Rules Engine Expansion

## Purpose

v47 is an engine pass, not a new faction-content pass. It targets the classes of rules that v46 could display correctly but could not always automate without guessing:

- arbitrary physical faction markers;
- persistent marked/detected/scanned target state;
- Enhancement bearer identity;
- per-Critical-Hit attack provenance;
- unusual reposition/reactive movement endpoints;
- missing reaction/event hooks;
- reusable player choices that persist for a phase/turn/round/battle.

The v46 Orks, Tyranids and base Space Marines faction-pack data remains the rules source for those factions. v47 adds reusable mechanics on top of that data.

## 1. Generic persistent rule state

`WarboardRuleState47` stores faction-owned state against a source unit, target unit or objective, plus optional values. A state can expire at:

- end of phase;
- end of turn;
- end of battle round;
- start of the owning faction's next turn;
- end of battle.

This is now used for effects such as:

- Bastion Task Force auspex-scanned targets;
- pinned and suppressed units;
- Heresy Undone eligibility/target restrictions;
- Subversion detected/cloaked targets;
- persistent datasheet/Stratagem choices;
- Adaptive Biology's permanent 4+ Feel No Pain upgrade.

## 2. Physical faction marker system

`WarboardMarkerSystem47` creates selectable physical markers on the battlefield and validates placement against reusable constraints:

- battlefield boundary;
- maximum distance from a source unit or reference point;
- minimum enemy distance;
- owner/faction;
- marker type;
- rule lifetime.

### Tyranid Tunnel Markers

For Subterranean Assault, when a BURROWER unit is detected entering the battlefield from Reserves, v47 opens legal placement for a circular 40 mm Tunnel Marker:

- within 1" of that unit;
- more than 3" horizontally from enemy units.

Tunnel Markers are tracked as real rule objects. If a non-AIRCRAFT enemy unit ends a move within 3", the marker is removed.

`TUNNEL NETWORK` now uses the actual tracked markers and the generic reposition engine rather than being a log-only card.

## 3. Enhancement bearer assignment

`WarboardEnhancementRegistry47` synchronises Enhancements found in the pasted New Recruit roster manifest, but it still refuses to guess the bearer.

A new Enhancement panel allows the player to assign every taken Enhancement to the actual imported unit. Where the source card exposes a safely machine-readable `MODEL ONLY` / `UNIT ONLY` restriction, v47 filters and validates bearer candidates. If the source wording cannot be safely interpreted, Warboard does not invent an eligibility restriction.

A standard-faction army with a taken Enhancement and no assigned bearer is **not ready for deployment**. This prevents passive Enhancement effects from being silently omitted.

The assignment is then available to all generic attack/save/OC/ability hooks.

### Passives migrated to bearer-aware automation

The v47 layer includes deterministic handling for a useful set of supplied-pack Enhancements, including examples such as:

- Artificer-style Save/FNP passives;
- Stoic Defender objective FNP and Battle-shock OC exception;
- The Flesh Is Weak / Supa-Cybork / other direct bearer FNP values;
- Adaptive Biology's 5+ FNP and permanent 4+ upgrade after the bearer is wounded at the start of a turn;
- Eye of the Primarch Precision assignment;
- Fusillade Lethal Hits and Pyromancy-dependent Sustained Hits 1;
- Power of the Hive Mind psychic Strength/AP improvement;
- The Imperium's Sword bearer melee +1 Attack;
- direct Stealth/Lone Operative/Infiltrators grants where the source wording is unambiguous;
- direct detection-range modifiers such as Cryptophotaic Camouflage and Telepathy Obfuscation.

The parser is conservative: an ambiguous or activated once-per-battle clause is not converted into an always-on passive.

## 4. Per-die Critical Hit / Critical Wound provenance

v46's combat code primarily described a weapon volley with shared booleans such as `precision`. That cannot correctly represent a rule where **only attacks generated by Critical Hits** gain Precision.

v47 introduces `WarboardAttackDieState47` and a per-attack ledger. Final hit and wound results can retain:

- roll;
- success/failure;
- Critical Hit / Critical Wound;
- Precision provenance;
- Lethal Hit provenance;
- Devastating Wound provenance;
- Sustained Hits contribution;
- reroll field for reaction consumers where the resolver has that information.

Both the automatic `RulesEngine` path and the staged `InteractiveAttackController` path are patched.

### Hive Predators

Tyranid Invasion Fleet `HIVE PREDATORS` now grants Precision **only to Critical Hits against CHARACTER targets**. It no longer has to promote the entire weapon pool to Precision.

In the interactive resolver, save rolls can now use different allocation/save targets within the same volley when some successful attacks have Precision and others do not.

## 5. Hidden / detection state is consumed by visibility

Warboard already has an Edition 11 Hidden/detection-range visibility path in `Core11CanSeeModel`. v47 connects the generic faction state layer to that calculation.

Examples now represented through the same reusable hook include:

- Subversion Assets `Transhuman Perception`: detected enemy +3" detection range;
- `CLOAKED POSITION`: -3" detection range;
- Cryptophotaic Camouflage Upgrade: -3" detection range;
- Obfuscation while using Telepathy Discipline: -3" detection range.

`DEATH IN THE DARK UPGRADE` can also query the real Hidden state and apply its +1 Hit against a hidden target.

This is deliberately a generic detection-range modifier hook rather than special-casing one detachment inside the core visibility function.

## 6. Rich rules/reaction event bus

`WarboardRuleEventBus47` sits above the existing `GameEventBus`. It mirrors core events and adds richer attack/state transitions, including:

- unit selected as an attack/charge target;
- final resolved hit;
- Critical Hit;
- final resolved wound;
- Critical Wound;
- attack summary;
- unit entered Reserves;
- unit set up from Reserves;
- model/unit destroyed;
- objective-control change;
- marker placed/removed;
- generic datasheet/rule choice made.

This gives future faction code a stable trigger surface instead of adding another faction name to `GameController` for every reaction.

### Exact reaction example

Subversion Assets `CLOAKED POSITION` now opens from the rich event layer at the **start of the opponent's Movement phase**, offers eligible unengaged PHOBOS/SCOUT SQUAD units, spends CP through the normal Stratagem system, and applies the live detection-range state if accepted.

## 7. Generic special placement/reposition engine

`WarboardSpecialPlacement47` provides a reusable endpoint-validation flow for rules that remove/reposition/reactively move a unit. Requests can specify:

- maximum translation distance;
- minimum enemy distance;
- must finish within range of a selected marker;
- must finish closer to a selected unit/objective;
- must finish unengaged;
- normal board/coherency/no-overlap validation;
- completion/cancel callbacks.

`TUNNEL NETWORK` is the first supplied-faction rule migrated onto this engine.

This is an endpoint legality engine. It does **not** pretend that every possible route-specific rule (for example, measuring exactly which >4" terrain section a model crossed) is solved when the current movement representation cannot prove that route.

## 8. Generic choice state

`WarboardDatasheetChoice47` gives faction/datasheet rules a reusable player choice whose result is stored with the correct lifetime and source unit.

`LIGHT OF VENGEANCE` uses this to choose Lethal Hits or Sustained Hits 1 and then applies the selected ability only under the source rule's scanned/BATTLELINE condition.

## Bastion Task Force migrated state interactions

The v47 layer now models the supplied Bastion state chain instead of treating it as disconnected cards:

- BATTLELINE attacks that score hits mark an enemy as auspex scanned;
- Traditional mode asks the player whether their manually resolved attack scored a hit before creating that state;
- scanned targets cause the detachment's Hit re-roll interaction;
- `CODEX DISCIPLINE` adds its Hit/Wound re-roll states;
- `GUIDED DISRUPTION` creates a pinned target (-2 Move, -2 Charge) until the owning player's next turn;
- `SHOCK BOMBARDMENT` creates suppressed (-1 Hit) state;
- `LIGHT OF VENGEANCE` stores and consumes the selected weapon ability;
- `HERESY UNDONE` allows the exceptional post-Advance/Fall-Back shoot/charge permissions but rejects non-scanned targets.

## Still deliberately not guessed

v47 substantially reduces the v46 manual list, but it does not claim that every unusual faction-pack sentence is now fully automatic. Remaining examples include:

- activated once-per-battle Enhancement clauses that require a new explicit activation timing/window if they are not otherwise migrated;
- exact route-specific geometry such as proving which height of terrain a model crossed during an unusual move;
- rules whose correct execution requires reserve-placement UI changes beyond endpoint repositioning;
- rules that rely on datasheet-specific information not present in the imported roster data;
- Traditional-mode dice outcomes that Warboard intentionally does not inspect.

Those rules remain on the exact source card/manual path rather than being approximated incorrectly.

## Installer design

The v47 installer:

1. requires a working v46 baseline;
2. runs its patch-engine self-test before staging project changes;
3. patches all baseline Core files into `Library/WarboardV47Staging` first;
4. requires unique exact or unique whitespace-tolerant source anchors;
5. performs structural method replacement for large staged attack methods;
6. validates the direct v47 payload before committing;
7. backs up replaced files under `Library/WarboardBackups/V47RulesEngine`;
8. rolls committed files back if commit fails.

The final authoritative compile test remains Unity on the project machine.
